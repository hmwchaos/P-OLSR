Paper mechanism to reproduce
----------------------------
The paper compares:
  - OLSR with link-quality / ETX behavior,
  - P-OLSR, an OLSR extension using GPS-based prediction.

The P-OLSR idea is:
  - Use positions available from UAV GPS/autopilot data.
  - Estimate whether a pair of UAVs is moving closer or farther apart.
  - Penalize links whose endpoints are moving apart.
  - Prefer routes that are likely to stay connected.

Baseline ETX:
  ETX(route) = sum_hop 1 / (phi(hop) * rho(hop))

Speed-weighted ETX:
  ETX(hop i,j) = exp(v_ij * beta) / (phi(hop) * rho(hop))

Instantaneous relative speed:
  v_tilde_ij = (d_l_ij - d_l_minus_1_ij) / (t_l - t_l_minus_1)

Smoothed relative speed:
  v_l_ij = gamma * v_tilde_ij + (1 - gamma) * v_l_minus_1_ij

Receiving ratio update:
  phi_l = alpha * h_l + (1 - alpha) * phi_l_minus_1

Notes:
  - phi is the forward receiving ratio.
  - rho is the reverse receiving ratio.
  - beta is the P-OLSR speed-weight parameter.
  - gamma is the P-OLSR speed-aging parameter.
  - HI is the Hello interval.


Paper parameters identified
---------------------------
UAV platform and radio:
  - Fixed-wing eBee UAVs.
  - 802.11n radio interface.
  - 20 MHz bandwidth in the 5 GHz band.
  - QPSK, code rate 1/2, one spatial stream.
  - UAV cruising speed described around 12 m/s in the routing discussion.
  - eBee platform also described around 57 km/h cruising speed.

Link-performance experiment:
  - 2 nodes: one ground node and one flying UAV.
  - UAV flies between two checkpoints 450 m apart.
  - Checkpoint turning radius: 30 m.
  - UAV height above ground: 75 m.
  - Ground node placed at one checkpoint center.
  - Traffic: 85 UDP datagrams per second, totaling 1 Mbit/s.
  - Datagrams delayed more than 5 s are treated as lost.
  - Metric: datagram loss rate (DLR).
  - Distance-to-DLR model used in this reproduction:
      DLR(d) = 1 / (1 + exp(-(-8.9 + 0.025 d)))
    This sign convention matches the paper text that DLR is low under about
    250 m and roughly 0.5 near 350 m.

3-node routing experiment:
  - Node 1: fixed destination on ground.
  - Node 2: flying UAV source.
  - Node 3: flying UAV relay.
  - HI = 0.5 s for both OLSR and P-OLSR.
  - OLSR alpha = 0.2.
  - P-OLSR alpha = 0.05.
  - P-OLSR beta = 0.2.
  - P-OLSR gamma = 0.04.
  - Node 2 flies 600 m west from Node 1, then returns.
  - Node 3 flies a circular trajectory with radius 30 m centered 250 m west
    from Node 1.
  - Both UAVs fly about 75 m above ground.
  - 10 loops were performed for each routing algorithm.
  - Average loop time was about 120 s.
  - Expected topology changes: direct path to two-hop path and back.

Large-network emulation:
  - 19 moving UAVs.
  - Node 2 scans a rectangular area and completes the trajectory in 380 s.
  - Nodes 1 and 3..19 are uniformly spread and circulate around waypoints.
  - Circular radius: 30 m.
  - Speed: 12 m/s.
  - Initial circular phase: uniformly distributed.
  - Traffic: 85 UDP datagrams per second, totaling 1 Mbit/s, from Node 2 to
    Node 1.
  - Outage definition: DLR > 0.2.
  - Repetitions: 10 per configuration.
  - Example P-OLSR configurations:
      alpha = 0.2, beta = 0.2, gamma varied.
      alpha = 0.2, gamma = 0.08, beta varied.
      beta = 0.2, gamma = 0.08, HI and alpha varied.

Mismatch and missing items
--------------------------
1. Full P-OLSR protocol integration is not implemented.
   Reason:
     A complete implementation would need changes in ns-3's OLSR message,
     neighbor, topology, MPR, and route-computation internals. That is outside
     the allowed write scope.

2. This reproduction does not use a full ns-3 Wi-Fi packet simulation.
   Reason:
     The paper's MAC-layer emulation used EMANE and real OLSRd/P-OLSRd
     processes. Recreating that exactly would need external tooling and
     protocol integration outside P-OLSR.

3. End-to-end delay is not produced as a packet-level metric.
   Reason:
     The current model computes expected DLR/PDR/goodput/outage from link
     delivery probabilities. Packet-level delay requires a full network stack
     and routing protocol implementation.

4. The exact large-network waypoint coordinates are not fully specified in the
   text source. The reproduction uses a deterministic relay grid and circular
   waypoint motion as the minimum substitute consistent with the paper.

5. The exact random GPS error model is not reproduced.
   Reason:
     The paper references an external GPS error characterization but does not
     provide all distribution parameters in the extracted source used here.

Protocol behavior implemented:
  - Native ns-3 OLSR is used as the baseline.
  - The copied local P-OLSR protocol is used as the predictive variant.
  - P-OLSR adds configurable attributes:
      EnablePrediction
      Beta
      Gamma
      LinkQualityAging
      DlrLogitIntercept
      DlrLogitSlope
      MaxLinkCost
  - Link delivery is estimated from the paper's logistic distance-to-DLR model.
  - phi and rho are smoothed receiving-ratio estimates.
  - Relative speed is estimated from distance changes between route-computation
    updates and smoothed with gamma.
  - Route cost uses:
      exp(relative_speed * beta) / (phi * rho)
  - The routing table is recomputed with Dijkstra over symmetric neighbor,
    two-hop neighbor, and topology tuples.

# V1.6.0 Experiment Notes

## 实验目的

V1.6.0 实验用于测试不同 HELLO 衰减周期对 P-OLSR 性能的影响。

本实验重点比较 `HelloDeadlineFactor` 取不同值时，P-OLSR 的链路质量估计、路由选择和最终网络性能是否发生明显变化。

## 实验变量

核心变量：

- `HelloDeadlineFactor`

含义：

- `HelloDeadlineFactor = 1.0` 表示 HELLO deadline 为 `1.0 * HelloInterval`。
- `HelloDeadlineFactor = 1.2` 表示 HELLO deadline 为 `1.2 * HelloInterval`。
- `HelloDeadlineFactor = 1.5` 表示 HELLO deadline 为 `1.5 * HelloInterval`。

该参数会影响 HELLO 丢失后 `phi` 的衰减触发时机。参数越小，链路接收率衰减越敏感；参数越大，链路质量估计越保守。

## 建议保持不变的参数

为保证不同实验之间可比，除 `HelloDeadlineFactor` 外，建议保持以下参数一致：

- `scenario=large`
- `helloInterval=1.0`
- `PredictionAlpha=0.1`
- `PredictionBeta=0.2`
- `PredictionGamma=0.08`
- `UsePredictionForMpr=false`
- `wirelessProfile=paper-dlr`
- `paperDlrMaxExtraLossDb=12.0`
- `RUNS=10`

## 输出目录说明

脚本会按参数生成版本化输出目录，例如：

```text

```

不同 deadline factor 会生成不同目录，避免互相覆盖。

## 需要重点比较的指标

建议比较以下指标：

- `goodput_mbps`
- `pdr`
- `dlr`
- `mean_delay_ms`
- `outage_time_s`

其中 `outage_time_s` 更适合观察链路质量估计和路由切换是否稳定。

## 结果解释注意事项

- 如果 `1.0HI`、`1.2HI` 和 `1.5HI` 结果非常接近，可能是因为 `ApplyHelloLossDecay()` 的检查周期仍由 HELLO timer 驱动，较小 deadline factor 在离散检查下触发时刻相同。
- 如果 deadline factor 变小后性能下降，可能说明 `phi` 衰减过快，导致路由对短时丢包过度敏感。
- 如果 deadline factor 变大后性能下降，可能说明链路质量估计滞后，失效链路被保留过久。
- 该实验用于比较 ns-3 当前实现中的衰减周期影响，不应直接等同于论文原始 EMANE/OLSRd 实验。

### 重要实验结论

- 当前代码中的 `paper-dlr` 信道是基于 ns-3 `YansWifiChannelHelper`、`PaperDlrPropagationLossModel` 和 `NakagamiPropagationLossModel` 的近似实现，不能严格等同于论文使用的 EMANE + IEEE 802.11 TGn Model D 信道。
- TGn Model D 是多径 MIMO 信道模型，包含 breakpoint 路径损耗、阴影衰落、Rician K-factor、cluster、tap delay、AoA/AoD 和角扩展等参数；当前代码只能近似距离相关损耗和随机衰落。
- 固定参数 `alpha=0.1, beta=0.05, gamma=0.04, HI=1.0` 下，当前结果中 P-OLSR 相比 OLSR-ETX 有更高 goodput、更低 outage time、DLR 和 delay，是 V1.7 中较好的参数组合之一。
- `UsePredictionForMpr=true` 在当前实现中会改善 OLSR-ETX 的部分指标，但会使 P-OLSR 指标变差；因此 V1.7 默认继续使用 `UsePredictionForMpr=false`。
- 当前 ns-3 结果更适合作为 P-OLSR 机制的近似验证，不能作为论文 EMANE/OLSRd 实验的严格复现。

### 运行命令示例

固定论文参数：

```bash
bash scratch/P-OLSR/run_v17_fixed_params.sh \
  --runs 10 \
  --version-prefix V1.7_fixed_paper_params \
  --alpha 0.2 \
  --beta 0.2 \
  --gamma 0.08 \
  --hi 1.0 \
  --hello-deadline-factor 1.4
```

HI=0.5 的单参数 sweep：

```bash
bash scratch/P-OLSR/run_v17_outage_sweeps.sh \
  --runs 10 \
  --version-prefix V1.7_HI0.5 \
  --hi 0.5 \
  --hello-deadline-factor 1.4 \
  --alpha 0.2 \
  --beta 0.2 \
  --gamma 0.08 \
  --alpha-values "0.1 0.2 0.4" \
  --beta-values "0.1 0.2" \
  --gamma-values "0.04 0.08 0.16"
```

### 注意事项

- V1.7 sweep 脚本一次只改变一个参数，另外两个参数使用命令行给定的基础值。
- `figures/` 是本地生成图片目录，已由 Git 忽略；需要保留论文或实验图片时，应明确选择单独文件或结果表格，而不是直接提交整个图片输出目录。
- 结果目录较大，提交前应确认是否需要纳入 Git，避免把临时 sweep 输出全部提交。
